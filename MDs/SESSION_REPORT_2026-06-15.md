## ✅ بخش ۳: سیستم سوییچ ماژولار LLM (رایگان/پولی) — جدید

### معماری: «رجیستری عددی» (به درخواست کاربر، مثل رجیستری ویندوز)
در `.env` فقط یک عدد `LLM_PROFILE` را عوض می‌کنی:

| عدد | پروفایل | backend | مدل |
|-----|---------|---------|-----|
| **1** | رایگان | `gemini_sdk` (SDK رسمی گوگل، چرخش کلید) | gemini-3.5-flash |
| **2** | پولی | `openai_compat` (ابرآروان) | Gemini-2.5-Flash-lite |
| **3** | ارزان (آزمایشی) | `openai_compat` (ابرآروان) | Gemma-4-31B-IT |

### پیاده‌سازی:
- **`config.py`:** دیکشنری `LLM_PROFILES` (ماژولار — افزودن شرکت جدید = یک ردیف). هر پروفایل: backend + text_model + light_model + vision_model + base_url + api_key_env. fallback امن به پروفایل ۱.
- **`ai_models.py`:** helper های `_active_profile()`، `_profile_uses_openai_compat()`، `_openai_compat_client()`، `_image_to_data_url()`. شاخه‌ی `openai_compat` به ۴ تابع اضافه شد: `generate_response`، `generate_response_stream`، `analyze_image_for_rag`، `refine_search_query`.
- **`.env`:** `LLM_PROFILE=1` (پیش‌فرض رایگان) + آدرس‌های آروان + جای خالی برای Gemma و شرکت‌های دیگر.

### تست‌های موفق:
- پروفایل ۱ (رایگان): import و vision OK.
- پروفایل ۲ (پولی آروان): non-stream + stream + refine + vision + **کل خط لوله RAG** → پاسخ بالینی صحیح با رفرنس.
- مدل آروان multimodal است (عکس می‌بیند) — تأیید شد.

### ⚠️ نکته‌ی مهم: embedding مستقل از LLM_PROFILE است
سوییچ LLM فقط مدلِ **تولید پاسخ** را عوض می‌کند. embedding RAG همیشه آروان bge-m3 می‌ماند (مستقل).

## ✅ بخش ۴: تقویت لایه‌ی تشخیص تصویر (Vision RAG)

### وضعیت معماری سه‌لایه‌ی پیشنهادی کاربر:
| لایه | وضعیت |
|------|--------|
| لایه ۲ (Vision-to-Text): توصیف عکس → جستجوی FAISS | ✅ فعال و کار می‌کند |
| لایه ۱ (CLIP بصری خام): `chroma_vision` | ❌ کد هست (`vision.py`)، دیتا اصلاً ساخته نشده |
| لایه ۳ (Fusion نهایی) | 🟡 از ساده به ساختاریافته ارتقا یافت (این جلسه) |

### بهبودهای این جلسه (بدون هزینه‌ی زیرساخت جدید):
1. **توصیف ساختاریافته:** `analyze_image_for_rag` حالا keyword های مورفولوژیک دقیق می‌خواهد (نوع سلول، هسته، سیتوپلاسم، رنگ‌آمیزی، inclusions) → جستجوی متنی دقیق‌تر.
2. **IMAGE FUSION PROTOCOL:** یک پرامپت ضدتوهم فقط در mode=image تزریق می‌شود: «اول مشاهده، بعد تقاطع با رفرنس، اگر هم‌خوان نبود صراحتاً بگو قطعی نیست + تست تکمیلی». لایه‌ی ۳ کاربر.

### تصمیم درباره‌ی CLIP (نظر دستیار):
- `clip-ViT-B-32` عمومی روی لام‌های پزشکی ضعیف است و می‌تواند توهم را زیاد کند.
- استخراج تصاویر PDF + ذخیره فایل = هزینه‌ی دیسک/نگهداری بالا (برخلاف هدف کمترین هزینه).
- **توصیه: فعلاً CLIP ساخته نشود.** لایه‌ی ۲+۳ تقویت‌شده ~۹۰٪ فایده را می‌دهد. توصیفات تصاویر کتاب (`**VISUAL_DESC:**`) از قبل در FAISS متنی ایندکس شده‌اند.
